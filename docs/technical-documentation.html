01Overview

The approved static HTML prototype is being rebuilt as a production web application with a content management system (CMS).

  • The website looks and behaves like the approved prototype on desktop, tablet and mobile.
  • The CMS lets PLG Acachet's team update text, images, videos, links and logos, and add, remove, reorder or hide whole sections of a page, without a developer.
  • Pages are built from a shared library of sections such as Banner, Text with image, Cards and Key numbers. New pages reuse them, which keeps the design consistent and lowers the cost of each new page.

04Content model

Pages

  • Page name and URL name. The web address is worked out automatically, including nested pages such as /about/our-story or /legal/terms. The breadcrumb at the top of inner pages is built from this page tree automatically.
  • Sections: the ordered list of content blocks.
  • SEO: page title, description and share image for search engines and social media.
  • Drafts, versions and scheduling: changes save as drafts automatically, can be previewed live, published when ready or scheduled, and earlier versions can be restored.

05Editing workflow

  1. Sign in at /admin.
  2. Open Pages and choose a page.
  3. Edit text and images inside a section. Drag sections to reorder, use Add Section to insert one, or use Section settings → Hide this section to take one off the page without deleting it.
  4. Click the eye icon for a live preview beside the editor, at desktop, tablet and mobile sizes. Changes save as a draft and are not public yet.
  5. Click Publish changes to put them live, or schedule them.
  6. Header & footer (under Settings) controls menus, footer links and the site-wide "Start a conversation" banner on every page.
  7. Messages from the website appear under Inbox → Form messages.

A detailed, plain-language Content Editor Guide (every section and option, buttons, images, publishing, and what each change affects) is provided separately for the content team.

06Website features

  • Responsive: matches the prototype on desktop, tablet (card rows become swipeable) and mobile.
  • Motion from the prototype: showreel intro, scroll reveals, stacking panels, auto-advancing key numbers, word-by-word statement and lead paragraph, banner and background parallax, drawn diagram lines, counting facts, a highlighted group structure, expanding link tiles, and a "View" cursor on case studies. All motion respects the visitor's reduced-motion setting.
  • Navigation: the current page is highlighted in the menu, inner pages have an automatic breadcrumb, and long pages have a section menu that follows the reader (swipeable on phones).
  • Accessibility: skip-to-content link, keyboard-operable menu (Escape closes it), labelled controls, a pause button for the background video, and alt text managed in the CMS.
  • Performance: static pages, images resized and converted (WebP/AVIF) for each device, self-hosted fonts, the showreel pauses when off screen, and scroll effects run at most once per frame.
  • SEO: per-page title and description, canonical URLs, share images, and automatic sitemap.xml and robots.txt.
  • Forms: checked in the browser and on the server, protected by a spam trap, and stored in the CMS inbox. The job application form only accepts roles that are currently open and has keyboard-operable dropdowns.
  • Case studies: filter by service with counts; each case study has its own address (/our-work#case-…) that can be shared, closes with Esc, keeps keyboard focus inside while open, and updates the browser tab title and page description.
  • Careers: open roles filter by team with counts and expand in place; "Apply for this role" jumps to the form with the role and discipline filled in.

07Security

  • The CMS requires sign-in. Passwords are hashed and sessions are signed with a secret key.
  • Role-based permissions (Admin and Editor). Form messages can only be created by the website's form, never through the CMS API.
  • Draft content is visible only to signed-in users through preview; the public site shows published content only.
  • Secrets such as the database connection and signing keys live in environment variables, never in the code.
  • /admin, /api and the preview routes are excluded from search engines.

08Hosting & deployment

Proposed production setup (AWS, UAE region)

The website is being built for the hosting plan in PLG Acachet: Proposed Hosting Architecture. Region: AWS Middle East (UAE), me-central-1, the AWS region closest to Dubai.

ComponentAWS servicePurpose

Ready in the application: uploads go to S3 once the bucket is configured, media can be served from the CDN, publishing clears the changed page from the CDN automatically, email works with Amazon SES, and /next/health is available for monitoring. Each is switched on by configuration at deployment, with no code changes, so hosting choices can still change.

Images and videos: images are delivered in several sizes in modern formats (AVIF/WebP), so each device downloads only what it needs. Background videos are optimised MP4 files on S3 delivered through CloudFront; the banner can take a lighter video for phones, and a preview image shows instantly while the video loads.

Release process

  1. Database changes are versioned as migrations and applied with npm run migrate before a release.
  2. npm run build produces the optimised site and npm run start serves it on the EC2 server.
  3. Recommended environments: staging for review and production, each with its own database and storage.

Backups

RDS automated daily backups with point-in-time recovery, a snapshot before each release, and versioning on the S3 media bucket.

Local installation

Developers can run the full website and CMS on their own computer with the step-by-step local setup guide (requirements, installation, database options, troubleshooting). No cloud account is needed for local development.
