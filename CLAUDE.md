# PLG Acachet website — project knowledge base

Read this before adding a feature. It's meant to replace reading the whole codebase: it records how things are built, why, and the traps already hit.
## Documentation rule (user requirement — mandatory)
**Every new feature, page, section/block, field, option, collection, integration, setting or decision updates ALL related documents in the same change.** A feature is not done until its docs are. Before finishing any task, go through this checklist and update each document the change touches:

| Document | Audience | Update when… |
|---|---|---|
| `CLAUDE.md` (this file) | Developers / Claude | Anything: blocks, fields, conventions, decisions, gotchas, status, commands |
| `docs/editor-guide.md` | **Client's content editors (non-technical)** | Any new or changed page, section, field, option, button style, collection, global, role, or editing behaviour. Use the exact CMS labels; add a row to "I want to…" and to "what affects what" where relevant; keep it plain-language |
| `docs/technical-documentation.md` **and** `.html` (republish to https://claude.ai/artifact/KbSfFWQBra4jU5UoRLDUQM) | Client (technical overview) | Sections list, content model, features, security, hosting, roadmap/status, items needed from client |
| `docs/architecture.md` | Client + developers | Flows, collections/content model, stack/packages, integrations, environments, env vars, deployment, decisions |
| `docs/hosting-architecture.md` | Client | Only when the client's hosting Google Doc changes (keep it a faithful copy) |
| `docs/local-setup.md` | Developers | Requirements, install steps, env vars, commands, seed behaviour, troubleshooting |
| `web/README.md` | Developers | Scripts, block catalogue, integrations, structure, "not done yet" |
| `web/.env.example` | Developers | Any new env var (with a comment) |
| `docs/backlog.md` + `docs/backlog-<feature>.md` | Developers + client | Any feature whose logic is skipped while it waits for a decision (UI stays); remove the row only when it is fully done |

## Pending features rule (user requirement — mandatory)
**If a section or feature is pending or waiting for a decision (client, access, legal…), build its UI exactly as the prototype shows it, skip only the logic, and add it to the backlog** in the same change: a row in `docs/backlog.md` plus a detail doc `docs/backlog-<feature>.md`. Never drop UI from a page because what's behind it is blocked. Make the inert UI obvious to developers (e.g. a file input with no `name` and a comment linking to the backlog doc). Example: the Join Us CV drop zone.

Also update "Last updated" dates on the docs you touch. In the wrap-up, list which docs were updated.

## Production target & integrations
Proposed production (decisions may change; keep everything swappable): **AWS me-central-1** — Route 53, ACM, CloudFront (caches whole site + media), **EC2** running `next start` (long-running Node, not serverless), **RDS PostgreSQL**, **S3** media, optional WAF, CloudWatch. Videos: plain MP4 on S3/CloudFront, no streaming service at launch (Bunny Stream/MediaConvert only if long videos with a player are needed later).

Every external service is an **env-gated integration** in `web/src/integrations/` — off locally, on in production, no code change:
| File | Switch | Does |
|---|---|---|
| `storage.ts` | `S3_BUCKET` (+ `S3_REGION` default me-central-1, `S3_PREFIX` default `media`, optional keys/endpoint) | `@payloadcms/storage-s3` for the `media` collection. `alwaysInsertFields: true` so the schema (media `prefix`, `_objectkey`) is identical with S3 on or off. `MEDIA_PUBLIC_URL` → file URLs point at the CDN (`disablePayloadAccessControl`) and next.config adds it to `images.remotePatterns` |
| `cdn.ts` | `CLOUDFRONT_DISTRIBUTION_ID` | `invalidateCdn(paths)`; called from `lib/revalidate.ts` `safeRevalidate` (page path, or `/*` for layout-wide changes) |
| `email.ts` | `SMTP_HOST` (+ port/user/pass/from) | `@payloadcms/email-nodemailer` (SES SMTP on AWS); unset → Payload logs emails to console |
Site settings that aren't integrations live in `lib/siteEnv.ts` (import-free, used by next.config, payload.config and app code): `siteUrl`, `indexingAllowed` (`SITE_INDEXING=off` → robots `Disallow: /`, noindex metadata, `X-Robots-Tag`, empty sitemap) and `checkProductionEnv()` (called at the top of `payload.config.ts`: in production throws if DATABASE_URL/PAYLOAD_SECRET/NEXT_PUBLIC_SITE_URL is missing, or the URL is localhost while S3/CloudFront/SMTP is set; local prod builds only warn). Both `NEXT_PUBLIC_SITE_URL` and `SITE_INDEXING` are **fixed at build time**. Security headers for every route are in `next.config.ts` `headers()` (HSTS without includeSubDomains, `X-Frame-Options: SAMEORIGIN` because live preview frames the site, nosniff, Referrer-Policy, Permissions-Policy, **CSP report-only**: add analytics/Cookiebot hosts there, enforce after staging shows no reports) and `poweredByHeader: false` (also stops withPayload's own X-Powered-By). Payload `csrf`/`cors` = `[siteUrl]` (+ localhost:3000/127.0.0.1:3000 in dev) and `maxDepth: 3`; still no `serverURL`.
Rules for new work: any new external service goes in `integrations/` behind an env var, is documented in `web/.env.example`, `docs/architecture.md` B9 and `docs/local-setup.md` §11, and must leave local dev working with the var unset. Don't assume serverless (EC2 is the target) or local disk persistence in production (media is on S3). Keep `/next/*`, `/admin`, `/api` uncacheable (CloudFront behaviours in architecture.md B3). Health check: `/next/health` (DB ping, `no-store`).
Images: `next/image` with `formats: ['image/avif','image/webp']`, 30-day `minimumCacheTTL`. Hero has optional `videoMobile` (`<source media="(max-width: 900px)">`) per the hosting plan.

## Architecture in one picture
```
Pages collection doc ── layout: Block[] ──► src/app/(frontend)/[[...slug]]/page.tsx
                                              └─ getPageByPath(path) ─► <RenderBlocks> ─► blocks/<Name>/Component.tsx
SiteSettings global ──► (frontend)/layout.tsx ─► Header / Footer
```
- **Route groups:** `src/app/(payload)` = generated admin/API (don't edit except via generate:importmap). `src/app/(frontend)` = site, own root layout. `src/app/robots.ts` must sit at app root (in a route group it 404s). `sitemap.ts` works inside `(frontend)`.
- **One catch-all page route** for every page. Path lookup: `pages.path` field.
- **`path` field** (`collections/Pages/computePath.ts`, field-level beforeChange): `/` for slug `home` without parent, else last nested-docs breadcrumb URL. Nested pages via `@payloadcms/plugin-nested-docs` (`parent`, `breadcrumbs`). `forwardTo` (sidebar relationship): the page route `redirect()`s to that page's path (e.g. `/legal` → `/legal/terms`); forwarding pages are excluded from the sitemap (`getSitemapPaths`).
- **SEO:** `@payloadcms/plugin-seo` with `tabbedUI` — it requires the Pages collection's **first field to be a `tabs` field** (it appends an "SEO" tab). `title` + `layout` live in the "Page sections" tab; `slug`, `path` are sidebar fields after the tabs.
- **Drafts/live preview:** Pages have drafts + autosave (600ms); **no schedulePublish** (switched off 2026-11-19: nothing ran the queued job and PLG doesn't need it; turning it back on needs a `jobs` autoRun config and brings back the `payload_jobs` tables). Admin preview URL = `/next/preview?path=…&secret=PREVIEW_SECRET` (route in `(frontend)/next/preview`, can't live under `/api` because Payload owns `/api/*`), enables Next draftMode → `getPageByPath` fetches `draft: true`; `LivePreviewListener` (RefreshRouteOnSave) refreshes on save. Exit: `/next/exit-preview`.
- **Linked pages are slim:** Pages has `defaultPopulate: { title, slug, path, breadcrumbs }` (CMS-3), so a page link anywhere (buttons, tiles, menus, Legal switcher, `forwardTo`) only carries those fields. If a component ever needs more of a linked page, add the field there, not a deeper query.
- **Breadcrumbs field** is declared in Pages itself with `createBreadcrumbsField('pages', { admin: { hidden: true } })` (the plugin then uses ours): hidden in the admin because the plugin rewrites it on every save (CMS-5). Same field and data as before.
- **Revalidation:** Pages (`collections/Pages/revalidate.ts`): beforeChange `rememberLivePage` reads the page's **main record** (`payload.db.findOne`), afterChange reads it again and compares. Draft saves (autosave/Save draft) never touch the main record and return a draft doc → nothing revalidated. Content-only publish → that page's path. First publish, unpublish (admin sends PATCH without `draft` + `_status: draft`), path, title or `forwardTo` change → whole layout (menus, buttons, Legal switcher, sitemap on other pages). Don't compare `previousDoc`: it's the latest *version* (often the draft that already had the new title/slug), so renames done through the admin would be missed. afterDelete of a published page → whole layout. SiteSettings, Partners, CaseStudies, TeamMembers, Roles afterChange → revalidate whole layout; the four collections also afterDelete (`revalidateSiteAfterDelete`). Media: `revalidateSiteAfterUpdate` (edits only, a fresh upload is on no page yet) + `revalidateSiteAfterDelete` (REVAL-1). `lib/revalidate.ts` `safeRevalidate` swallows errors because scripts (seed) run outside Next. Seed passes `context: { disableRevalidate: true }`.
- **Data access:** only `src/lib/payload.ts` (server-only): `getPageByPath`, `getAllPagePaths`, `getSiteSettings`, `getPartners`, `getTeamMembers`, `getOpenRoles` (roles with `isOpen`), `getCaseStudies` (sortOrder, depth 1), `getSitemapPaths` (published, not forwarding). Add new getters there. Components take props; data-driven blocks (e.g. LogoMarquee) may be async server components that call getters.
- **Types:** `src/payload-types.ts` generated. Every block config sets `interfaceName: '<Name>Block'` so components import `XBlock` types. Link fields have **no** interfaceName (shapes differ per options → would collide); use `LinkData` from `lib/links.ts`.

## The three reuse layers (don't skip a layer)
1. **UI primitives** `src/components/ui/` — no CMS knowledge:
   `Button` (pill + rotating arrow; `primary|ghost|dark`, `size sm`, `reveal`, `revealDelay`; heights are **min-height** 52/44 (PageHero `.ctas` 46 with `padding-block: 11px`) so long labels wrap and the pill grows: never set a fixed `height` on a button), `CMSLink` (resolves CMS link → Button or plain link via `as="text"`), `Media` (Payload media doc → next/image; SVG → plain img; focal point → object-position; `fill` mode), `RichText` (Lexical renderer, internal links → page path), `MultilineText` (textarea newlines → `<br>`), `SectionHeader` (eyebrow + `.h1` title, gradient toggle, reveal delays, `bare` = no wrapper div), `Section` (id + `tone="light"` → `data-nav-tone`), `Parallax` (`mode="top"` banner y×factor / `mode="section"` drifts ±range/2 as its parent section crosses the screen), `WordReveal` (words light up with scroll; `highlightFrom` + `start`/`span` tuning), `Slider` (≤1100px snap slider, drag+momentum, arrows; `tone`, `dots` default off, `barClassName`; the track is a focusable labelled region (`label`, default "Slides") for keyboard scrolling), `Marquee` (renders set twice), `CustomCursor` (global; shows over `[data-cursor]`), `RevealObserver` (global; adds `.in` to `[data-reveal]`/`[data-panel]`/`[data-inview]`, also watches DOM mutations; `data-inview` has no styles: use it to start a block's own `.in` animation; Home (showreel) hides every `[data-reveal]` until `.in`, threshold .15; inner pages only hide those below the fold when found (`.pre`, hidden at once), threshold .12, like the prototype), `StickyBar` (client; 0-height marker + sticky `.snav` bar, `.stuck`, steps aside unless `body.nav-hidden`, drag-scroll; links or `aria-pressed` buttons; `variant="tabs"`: page links with `aria-current="page"` underlined, 18px/14px on phones; used by Services menu, Our Work filter, Legal switcher), `Marked` + `paragraphsOf` (`[to confirm]` text → orange `<mark>`; textarea → paragraphs on blank lines).
2. **Field groups** `src/fields/`: `link()` / `linkArray()` (label, appearance, type page|section|url, page, section, url, newTab; conditional fields; `url` validated by `validateSafeUrl`), `safeUrl.ts` (`validateSafeUrl` for any text field holding an address: only https/http/mailto/tel/`/…`/`#…`; `withSafeUrl(defaultFields)` for Lexical `LinkFeature({ fields })`; both editors in `richText.ts` use it: **every new address field must use it**, E2E-11-4), `sectionHeader()` (eyebrow, title textarea, gradientTitle), `sectionSettings({ theme, defaultTheme })` (collapsible: anchorId, navLabel, theme, hideSection — **end every block with it**), `richText()` (small Lexical editor: paragraph/bold/italic/link), `mediaField({ accept })`, `slugField(from)`, `ctaFields({ required })` (call-to-action content: used by `site-settings.cta` and `ctaBanner.custom`). Row labels: `@/fields/LinkRowLabel#LinkRowLabel` / `#ItemRowLabel`.
3. **Blocks** `src/blocks/<Name>/{config.ts, Component.tsx, Component.module.css, …}`; registered in `blocks/index.ts` (configs, picker order) and `blocks/RenderBlocks.tsx` (component map, typed so a missing entry is a TS error). `RenderBlocks` skips `hideSection` and passes every block the **page context** (`blocks/context.ts` `BlockContext`: `page` {title, path, breadcrumbs} + `navItems` derived from visible blocks with `anchorId` && `navLabel`). Components type props as `XBlock & BlockContext` when they need it.

**Rule for every new page:** reuse a block → else add a variant/option to an existing block → only then a new block. Variants are a `select` (`variant`, `cardStyle`, `formType`) and a `switch` in the component (see `Hero/Component.tsx` → `variants/`).

## Frontend conventions
- **CSS:** globals only in `src/styles/` (tokens, reset, `.eyebrow .h1 .grad .body`, `.arr` icon, `[data-reveal]`, `fadeIn` keyframes). Everything else in the component's module. Port prototype rules as-is, renaming selectors; state classes (`.in`, `.on`, `.is-hidden`) become module classes toggled in JS or `:global(.in)` when set by RevealObserver.
- Breakpoints from prototype: 1280, 1100 (sliders kick in), 900 (mobile). `--gutter` 72/48/24.
- Reveal: `data-reveal=""` (or `"scale"`/`"fade"`), delay via `style={{'--d': '.16s'}}`. Buttons: `reveal revealDelay={0.24}`. Hidden-state rules in `base.css` use `:where(main:has([data-hero='showreel']))` / `:where(.pre)` so they keep plain `[data-reveal]` specificity.
- Home vs inner pages: Home-only looks hang off `main:has([data-hero='showreel'])` (attribute set by ShowreelHero): compact footer (`Footer.module.css`; the inner-page footer is the default), hide-all reveals. Inner-page looks shared with the prototype's inner pages (16px phone button labels) are set by `main:has(PageHero .hero)` and `main:has(.lhero)` (Legal).
- Reset: `*` only (like the prototype), so `::before`/`::after` stay content-box: a 14px circle with a 1px border is 16px wide.
- Header tone: sections with white background must pass `tone="light"` to `<Section>` (or set `data-nav-tone="light"`); footer already does.
- Sideways drag rows (section menu, filter chips): `hooks/useDragScroll(ref, draggingClass, fadePx)` → mouse drag, click swallowing, `--fl/--fr` edge-fade vars; returns a `dragging` ref.
- Never let React own the className of an element that RevealObserver/imperative code also toggles classes on (it rewrites the whole attribute on re-render): put changing state in a `data-*` attribute instead (see `openRoles` `data-open`).
- Scroll effects: use `useRafScroll(read, write)` — one shared rAF loop, all reads before writes. Never add raw scroll listeners for visual effects.
- Client components only for behaviour; keep markup rendering in server components where possible (e.g. `StackedPanels/Component.tsx` server + `StackedPanelsScroll.tsx` client wrapper).
- Blocks that need their place on the page (e.g. "02 / 04", every-other background) use `position` from BlockContext (computed in RenderBlocks among visible blocks of the same type).
- Section wrapper ids come from `anchorId` (editor-set). Seed sets the prototype's ids (`about`, `services`, `stack`, `stats`, `work`, `statement`, `contact`).
- Fixed routes the code knows: `lib/routes.ts` (`caseStudyHref(slug)` → `/our-work#case-<slug>`).
- Links that honour **Open in a new tab**: spread `newTabProps(link.newTab)` from `lib/links.ts` on every `<a>`/`<Link>` built from CMS link data (Button/CMSLink already do). `SectionNavItem` carries `newTab`.
- **Long text never widens the page** (E2E-5-1): `body` has `overflow-wrap: break-word`; labels use `overflow-wrap: anywhere` instead of `white-space: nowrap`. A title that must stay on one line (Home cards `.head .h1`) uses `width: max-content` + a `max-width` to the right gutter. To check a change, the long-text stress test: put a ~100-character sentence in every short text leaf of `main` at 1440/1000/375/320 and compare `scrollWidth`.
- Forms: client forms use `useLockedActionState(action)` from `blocks/Form/formHelpers.tsx` (returns `[state, action, pending, lock]`; in onSubmit: `if (lock.isBusy()) return void e.preventDefault()` first, `lock.send(e)` once valid: it `preventDefault`s and dispatches the FormData in `startTransition`) so quick double clicks send once (E2E-3-2) and **React 19 doesn't empty the form** (it resets every field after a form `action`, even when the server refused the send: E2E-3-5). Keep `action={action}` on the form for no-JS; flagged fields get `{...fieldA11y(errors, 'name', '<id>-err')}` with the error span carrying that id, and `<ErrorSummary errors={errors} />` (screen-reader-only `role="alert"`, uses global `.sr-only`). Custom `Select` takes `errorId`.
- Forms: server actions in `src/app/(frontend)/actions.ts` (`submitEnquiry`, `submitApplication`, `submitContact`: name/company ≥2, work email with a 2+ letter ending, message 10–1500, consent required, interests saved one per line and only those offered by a `contact` Form block on the page the form was sent from (`contactChoices`, E2E-3-3)) validate + save to `form-submissions` with `overrideAccess`; honeypot field `company_website`. `submitApplication` checks discipline against `DISCIPLINES`, link must be http(s), and stores the role **title** only if the posted id is a role with `isOpen` (else "General application"). Client forms use `useActionState`; no setState-in-effect. File uploads: see `docs/backlog-cv-upload.md` before adding any (private S3, not the media bucket).

## Migrations
Dev uses Payload's automatic schema push. Before handing over/deploying a schema change: `npm run migrate:create -- <name>` and commit `src/migrations/*`. Migrations so far: `20261118_161446_initial`, `20261119_174010_users_admin_default_no_scheduling` (drops the unused `payload_jobs` tables, users.role default → admin; tested 2026-11-19 on an empty UTF-8 DB: both run, schema identical to the local DB: 1564 columns, 303 enum values, 589 indexes, 368 constraints, 0 differences; the local push-built DB got the same SQL by hand). The 10 earlier migrations were squashed into it on 2026-11-18 (E2E-13-1: they couldn't build an empty DB). Nothing was deployed, and the local DB is push-built (its `payload_migrations` holds only `dev`), so no database depends on the old files. Verified: an empty UTF-8 DB → `migrate` → schema identical to the push-built local DB (1592 columns, 108 enums, 605 indexes, 372 constraints, 0 differences) → `seed` → production build → all 11 pages render the same text as local.
- **Testing a migration** (do it for every new one): start a second empty DB (embedded-postgres on port 5434 with `initdbFlags: ['--encoding=UTF8', '--locale=C']`, data in the scratchpad), then `DATABASE_URL=…5434… NODE_ENV=production npx payload migrate`, compare the schema with the local DB (`information_schema.columns`, `pg_enum`, `pg_indexes`, `pg_constraint`), then seed it. The seed writes media into the shared `web/media` folder, adding `-1` copies: restore the folder afterwards.
- **Never add an enum value and use it in the same migration** (`ALTER TYPE … ADD VALUE` + `SET DEFAULT`/insert with that value): Postgres refuses inside one transaction. Split it into two migrations.

## Gotchas already hit (don't repeat)
- `serverURL` in payload config makes media URLs absolute → next/image "unconfigured host" error. It's removed; keep URLs relative.
- `payload run` + non-awaited promise = script silently does nothing.
- React-hooks lint: no ref writes during render (update refs in an effect), no setState inside effects (derive state / "adjust state on prop change" pattern / useActionState wrapper), no reassigning variables inside render callbacks.
- Header className is React-managed but scroll classes are toggled imperatively → after `open` changes, call `requestScrollUpdate()` to re-apply them.
- Block CSS (`width: 100%`, padding) beat Slider CSS by load order → Slider forces `display/width/margin-inline` with `!important`; blocks tune slider spacing only through `--slider-*` variables. Don't set padding on a slider track except in a `min-width: 1101px` query.
- Prototype CSS quirks we intentionally match: mobile swipe dots never show (later rule overrides) → `Slider dots` default false; footer mobile gap is `12px 20px` (later rule overrides 24px); button label "roll" animation is disabled by later rules (arrow just rotates 45°).
- `robots.ts` inside a route group → 404.
- Browser-pane screenshots of background tabs are throttled/mid-transition; front the tab and wait before judging visuals.
- No Python on this machine; use node/sed for scripted edits. Use the session scratchpad for temp files, not `/tmp`. Scripts with JS template literals or many quotes: write them to a scratchpad file and run it (inline `node -e` / heredocs in the Bash tool mangle backticks and `${}`).
- **Bash tool heredocs/inline node strip backslashes** (`\n`, `\s`) and mangle backticks: for scripted edits write the script with the Write tool into the scratchpad and run `node <file>`, or use Edit.
- A dev server stopped by Claude Code's memory reaper may leave the Next child process running on :3000 (new `npm run dev` then exits "port in use"). Find it with `Get-NetTCPConnection -LocalPort 3000` and kill its parent `next dev`.
- **Postgres identifiers max 63 characters**: nested arrays/selects inside blocks generate long names (`enum__pages_v_blocks_legal_document_sections_cookie_table_category` broke Payload init and the dev server). Set `enumName` on selects and `dbName` on arrays when nesting deep; watch for the "exceed Postgres's 63-character limit" warning in `generate:types`.
- **Migrations were never run on an empty DB** (local DB is built by dev schema push). On 2026-11-18 a fresh UTF-8 DB stopped at migration 3 (`ALTER TYPE … ADD VALUE` then using the value in the same migration). Fixed by squashing into one `initial` (see Migrations). Test every new migration on an empty DB before deploying.
- `TaskStop` on a background `npm run start` leaves the `next start` child on :3000: find it with `Get-NetTCPConnection -LocalPort 3000` and stop it.
- **Local embedded-postgres was WIN1252** (Windows code page) until 2026-11-18, so Arabic/emoji failed to save (E2E-3-1). Since then:
  - `scripts/db.mjs` creates clusters with `initdbFlags: ['--encoding=UTF8', '--locale=C']` and warns on start if the cluster isn't UTF-8.
  - `scripts/db-to-utf8.mjs` (`npm run db:utf8`) converts an old cluster: it builds the schema with `payload migrate` on a new UTF-8 cluster, copies every table with `row_to_json` → `json_populate_recordset` (never alias the row `x`: team-members has an `x` column), keeps the old id counters, checks row counts, and swaps folders (old kept as `.postgres-old-<date>`, ignored by git via `/.postgres*`). `PG_DATA_DIR` points it at a copy for testing.
  - Payload's dev push accepts the migrated schema; column order differs from the push-built one, which is harmless.
  - RDS must be UTF-8.
- **Right after a save, the very first request can still get the cached page** (Next applies `revalidatePath` after the response): automated revalidation tests must wait ~1 s before checking (E2E-4-1).
- **OneDrive turns `.next` folders into read-only cloud placeholders** (ReparsePoint): `npm run build` then fails with `EPERM … unlink '.next\static\…'`. Stop `next start`, `attrib -R <dir> /S /D`, delete it (or all of `.next`), build again.
- Admin UI tests: blocks/array rows and collapsibles start collapsed (`.collapsible--collapsed`; click `.collapsible__toggle` in rounds) and Payload only renders fields once they scroll into view, so expand, then scroll the form, before looking for `#field-…` inputs (ids: `field-layout__0__sections__1__mustNote`).

- Offices: the Copy/Directions buttons live in their own `<dd className={styles.act}>` with `display: contents` (valid `<dl>`, identical grid layout).

## Verifying a page
1. `npm run lint && npm run typecheck && npm run build` (DB running).
2. Compare with prototype at 1440, 1000 and 375 widths: run in both tabs
   `[...document.querySelectorAll('main > *')].map(e => Math.round(e.getBoundingClientRect().top+scrollY)+'/'+e.offsetHeight)` — section tops/heights should match exactly; then screenshot key sections.
   Also compare the footer height and `document.documentElement.scrollHeight`: the footer sits outside `main`, so section checks miss it (that's how FOOT-1 went unnoticed). Measuring several widths in one browser tab: load the page in a hidden same-origin iframe of exact width W; media queries follow the iframe width. Claude in Chrome truncates long JS results (~1000 chars) and blocks output containing URLs with query strings, so return compact strings.
3. Exercise interactions; check console + server logs.
   - **Revalidation tests** need a production build (`npm run build` + `npm run start`); dev renders every request fresh.
   - **Warm cache first**: request the page until `x-nextjs-cache: HIT` *before* the change. A page not requested since the last site-wide revalidation renders fresh anyway, which gives false passes.
   - **Admin publish**: wait until autosave finishes before clicking Publish (the button is disabled meanwhile and the click is lost).
4. In `/admin` as editor: edit, reorder, hide, live preview, publish.
